1. Quick revision: Regularization recap
The lecture starts by revisiting regularized Logistic Regression:
$$
\text{Loss}=\text{Log Loss}+\lambda\sum_j w_j^2
$$

In this form, \(\lambda\) controls the strength of L2 regularization.
Scikit-learn's LogisticRegression uses C, which is inversely related to regularization strength:
$$
C\propto\frac{1}{\lambda}
$$

C value    Regularization    Typical effect
C = 0.001    Strong    Coefficients are pushed toward smaller values
C = 10    Weak    Coefficients are less strongly penalized
Remember: smaller C means stronger regularization; larger C means weaker regularization. The exact coefficient values and model complexity depend on the data and other settings.

2. KNN Imputation — filling missing values
2.1 What is imputation?
Imputation means replacing missing values with estimated values instead of automatically deleting the affected row or column.
Common approaches:
Feature type    Simple approach    When it can be useful
Numerical    Mean    A quick baseline when the mean is suitable
Numerical    Median    Often more robust when outliers are present
Categorical    Mode (most frequent value)    When replacing a missing category with the most common category is reasonable
Numerical    KNN Imputation    When similar records may help estimate a missing value
Mean, median and mode are examples of simple, single-column imputation strategies. KNN Imputation instead uses information from similar rows. 


scikit-learn 1.9.1 documentation



2.2 The core intuition
Imagine a housing dataset where one apartment's balcony size is missing.
Instead of using the average balcony size of every apartment, we look for apartments similar to the one with the missing value—for example, apartments with similar area, number of rooms and location.
We then use the balcony sizes of the nearest suitable apartments to estimate the missing value.
The underlying assumption is:
Records that are similar on the observed features may have similar values for the feature that is missing.
This is an assumption, not a guarantee. If the selected features do not identify genuinely similar records, KNN imputation may produce poor estimates.
2.3 How KNN Imputation works
Suppose row \(x_3\) has a missing value in feature \(F_3\).
Step 1 — Identify the incomplete cell
The value of \(F_3\) in row \(x_3\) is NaN.

Step 2 — Calculate distances
Compare \(x_3\) with other rows using the features available for distance calculation.

Step 3 — Select the nearest eligible neighbours
For example, if \(k=2\), select the two closest rows that also have a known value for \(F_3\).

Step 4 — Estimate the missing value
Take the average of the neighbours' known \(F_3\) values, or use a distance-weighted average.

The lecture's example uses Euclidean distance and assumes that \(x_1\) and \(x_7\) are the two closest suitable neighbours.
For \(k=2\):
$$
\hat{x}_{3,F_3}=
\frac{x_{1,F_3}+x_{7,F_3}}{2}
$$

For \(k=3\), if \(x_5\) is also selected:
$$
\hat{x}_{3,F_3}=
\frac{x_{1,F_3}+x_{7,F_3}+x_{5,F_3}}{3}
$$

The hat symbol indicates an estimated value.
2.4 Worked numerical example
Suppose we have this small dataset:
Sample    \(F_1\)    \(F_2\)    \(F_3\)
\(x_1\)    0.20    0.80    12
\(x_2\)    0.85    0.10    45
\(x_3\)    0.25    0.75    NaN
\(x_4\)    0.30    0.90    18
We want to fill the missing \(F_3\) value in \(x_3\). We use \(F_1\) and \(F_2\) to calculate distances.
Distance from \(x_3\) to \(x_1\):
$$
d(x_3,x_1)=\sqrt{(0.25-0.20)^2+(0.75-0.80)^2}
$$

$$
=\sqrt{0.005}\approx0.0707
$$

Distance from \(x_3\) to \(x_2\):
$$
d(x_3,x_2)=\sqrt{(0.25-0.85)^2+(0.75-0.10)^2}
$$

$$
=\sqrt{0.7825}\approx0.8846
$$

Distance from \(x_3\) to \(x_4\):
$$
d(x_3,x_4)=\sqrt{(0.25-0.30)^2+(0.75-0.90)^2}
$$

$$
=\sqrt{0.025}\approx0.1581
$$

Therefore, the nearest two rows are \(x_1\) and \(x_4\).
For \(k=2\), the missing value becomes:
$$
\hat{x}_{3,F_3}=\frac{12+18}{2}=\boxed{15}
$$

Notice that \(x_2\), with an \(F_3\) value of 45, is excluded because it is much farther away.
This is the key difference from mean imputation: KNN estimates the value using local neighbours rather than the entire column.
2.5 Uniform versus distance-weighted imputation
The lecture mainly demonstrates a simple average. An additional useful option is to give closer neighbours more influence.
For example, one common weighting scheme is:
$$
w_i=\frac{1}{d_i}
$$

Then the estimate is:
$$
\hat{x}=\frac{\sum_i w_i x_i}{\sum_i w_i}
$$

Using our example:
- \(x_1\): value \(12\), distance \(0.0707\), weight approximately \(14.14\).
- \(x_4\): value \(18\), distance \(0.1581\), weight approximately \(6.32\).
The weighted estimate is approximately:
$$
\hat{x}=\frac{14.14(12)+6.32(18)}{14.14+6.32}
\approx\boxed{13.85}
$$

The closer row \(x_1\) has greater influence, so the estimate is closer to 12 than to 18.
Scikit-learn's KNNImputer supports both uniform and distance-based weighting.

2.6 An important implementation detail: missing-aware distance
The instructor explains that distance is calculated using available features. That is the right intuition, but a practical implementation needs more care.
Scikit-learn's default KNNImputer uses nan-Euclidean distance. It ignores feature coordinates that are missing in either row and adjusts for the number of coordinates that remain available:
$$
d_{\text{nan}}(x,y)=
\sqrt{\frac{p}{p_{\text{observed}}}
\sum_{\text{observed }j}(x_j-y_j)^2}
$$

Here:
- \(p\) = total number of features.
- \(p_{\text{observed}}\) = number of features observed in both rows.
This prevents the raw distance from automatically becoming smaller simply because fewer features were compared. If two rows have no common observed features, their distance is undefined.

2.7 The balcony example: Should we drop a column with 70% missing values?
Lecture example: Suppose 70% of a house-price dataset's Balcony Size values are missing.
Should we automatically drop the feature?
No. Balcony size might be an important predictor of price. The correct decision depends on the feature's business meaning, data quality and predictive usefulness.
A sensible workflow is:
1. Investigate why the values are missing.
2. Ask a domain expert or stakeholder whether the feature matters.
3. Build a quick baseline model using a simple imputation method.
4. Evaluate it on held-out data.
5. Compare alternatives, including KNN imputation or removing the feature.
6. Keep the approach that performs well and makes sense for the problem.
Additional clarification: 70% missingness does not automatically mean a feature is valuable, either. If “missing” actually means “no balcony,” the missingness itself may carry information. If it means “not recorded,” the interpretation is different. The meaning should be investigated rather than assumed.
2.8 Practical cautions
- Feature scaling: KNN uses distances. If one feature is measured in lakhs and another between 0 and 1, the larger-scale feature can dominate. Scaling is often necessary.
- Baseline first: KNN imputation is not automatically better than mean or median imputation. Compare results.
- Fit preprocessing on training data: Do not let information from the test set influence the imputer's fitted statistics or neighbour reference data.
- All-missing features: An entirely missing feature cannot provide neighbour values to estimate itself in the ordinary way; library behaviour and feature retention should be checked.
- Categorical features: A numeric KNN distance is not automatically meaningful for categories. Encoding them does not guarantee that Euclidean distance represents true similarity.

3. KNN for multiclass classification
3.1 What is multiclass classification?
In binary classification, the target has two classes—for example, Fraud and Genuine.
In multiclass classification, there are three or more classes. The lecture's illustration uses:
- Red class
- Green class
- Black class
A new point is assigned to one of those classes using the labels of its nearest neighbours.
3.2 How multiclass KNN works
The algorithm does not need a separate binary classifier for every class. It can directly compare the neighbours' class labels.
1. Choose \(k\).
2. Calculate the distance from the new point to the training points.
3. Find the \(k\) nearest neighbours.
4. Count the class votes.
5. Predict the class with the highest vote count.
Example with \(k=5\):
Class    Neighbours    Votes
Red    3    3
Green    1    1
Black    1    1
The prediction is Red, because Red has the most votes.
3.3 What happens when there is a tie?
Suppose three neighbours vote as follows:
Red    Green    Black
1    1    1
There is no majority winner.
The lecture suggests choosing randomly or using weighted KNN.
Distance-weighted voting: closer neighbours receive greater voting weight. A common choice is \(w_i=1/d_i\), with appropriate handling for zero distance.
This can break a tie in total weighted votes, but it does not guarantee that every possible tie disappears. Two classes could still have equal total weights.
An odd \(k\) often helps avoid ties in a binary classification problem, but it is not a universal solution for multiclass classification.
3.4 KNN versus Logistic Regression for multiclass problems
The lecture contrasts KNN with Logistic Regression, mentioning One-vs-Rest (OvR).
- KNN: directly votes among the classes represented by its neighbours.
- OvR: trains one binary classifier for each class against all remaining classes.
- OvO: trains classifiers for pairs of classes.
Technical update: It is too broad to say that Logistic Regression inherently supports only two classes and always requires OvR or OvO. Modern scikit-learn Logistic Regression supports multinomial loss for multiclass problems with most solvers; the liblinear solver is the notable binary-only exception unless wrapped in a strategy such as OvR.

3.5 Why KNN becomes expensive
The lecture highlights two major concerns.
A. Large training dataset
KNN is a lazy-learning approach: it typically retains the training data and performs much of its work when making predictions. A query may need distances computed against many stored samples.
B. High dimensionality
As features increase, distances can become less informative. This is part of the curse of dimensionality. The cost of distance computation also grows with the number of features.
The instructor suggests PCA (Principal Component Analysis) before KNN.
PCA can reduce dimensionality, but it is not a guaranteed fix. It should be evaluated because it can discard information useful for classification. Scale features appropriately before PCA when the feature units differ substantially.
3.6 Categorical data and distance
The lecture says KNN is generally more natural with numerical features. Categorical features often require encoding, but one-hot encoding can increase the number of dimensions and may make ordinary Euclidean distance less meaningful for the problem.
The important lesson is not “never use categorical features with KNN.” It is:
Choose a representation and distance metric that reflect meaningful similarity between records.

4. Imbalanced datasets
4.1 What does class imbalance mean?
A dataset is imbalanced when one target class occurs much more frequently than another.
The lecture uses fraud detection:
Transaction type    Number of records    Percentage
Genuine    990    99%
Fraud    10    1%
Total    1,000    100%
Fraud is the minority class; genuine transactions are the majority class.
The lecture also gives a rough class-ratio guide:
Majority : Minority    Lecture's description
50 : 50    Balanced
60 : 40    Slightly balanced
70 : 30    Slightly imbalanced
80 : 20 to 90 : 10    Imbalanced
95 : 5 and beyond    Extreme imbalance
These are teaching heuristics, not universal statistical boundaries. Whether a dataset is problematic depends on the application, the cost of mistakes, sample size and how difficult the minority class is to identify.
4.2 Why accuracy can be misleading
Imagine 1,000 transactions:
- 990 are genuine.
- 10 are fraudulent.
Now imagine a useless model that predicts Genuine for every transaction.
It gets 990 predictions correct:
$$
\text{Accuracy}=\frac{990}{1000}=99\%
$$

But it detects zero fraud cases.
This is why high accuracy alone does not prove that a model is useful on an imbalanced dataset.
4.3 Which metrics should we consider?
The lecture establishes that accuracy is not enough. These additional metrics help assess the model's behaviour:
Metric    What it tells us
Precision    Of the cases predicted positive, how many really were positive?
Recall    Of all actual positive cases, how many did the model find?
F1-score    Harmonic mean of precision and recall
Confusion matrix    Counts of correct and incorrect predictions by class
PR-AUC / Average Precision    How precision and recall trade off across thresholds
Balanced accuracy    Average recall across classes in a standard multiclass setting
For fraud detection, the positive class is often Fraud.
- High precision: fewer genuine transactions are incorrectly flagged.
- High recall: more actual fraud cases are detected.
Which metric matters most depends on the business costs. A useful model may need both strong fraud detection and an acceptable rate of false alarms.

5.1 Undersampling (downsampling)
Definition: Reduce the number of majority-class examples in the training data.
Suppose we have:
- Genuine: 900
- Fraud: 100
To balance the data using random undersampling, we could retain 100 genuine records and all 100 fraud records.
Class    Before    After
Genuine    900    100
Fraud    100    100
Total    1,000    200
What is the trade-off?
We have removed 800 genuine examples. Some may have contained valuable patterns about normal transactions.
The lecture connects this loss of information with underfitting and high bias. That can happen, but it is not guaranteed: if many discarded examples are redundant, undersampling can work well and can reduce training time.
Analogy: Imagine learning about the behaviour of customers but throwing away most of the examples of normal customers. You may lose useful knowledge about what normal behaviour looks like.
5.2 Oversampling (upsampling)
Definition: Increase the representation of the minority class in the training data.
Using the same original counts:
- Genuine: 900
- Fraud: 100
Random oversampling can duplicate minority-class records until there are 900 fraud examples.
Class    Before    After
Genuine    900    900
Fraud    100    900
Total    1,000    1,800
What is the trade-off?
Duplicating records does not create new independent information. A model may give repeated examples excessive influence and overfit to them, although overfitting is not inevitable for every model or dataset.
Analogy: If a student practises the same ten questions repeatedly, they may memorise those exact questions instead of learning the wider concept. Random oversampling can similarly repeat the same minority examples without adding new diversity.
5.3 Undersampling versus oversampling
Aspect    Undersampling    Random oversampling
What changes?    Removes majority examples    Duplicates minority examples
Main potential risk    Loss of useful information    Over-reliance on repeated examples
Training-set size    Decreases    Increases
Computational cost    Often lower    Often higher
Guaranteed to fail?    No    No
The lecture recommends considering SMOTE, cost-sensitive methods and boosting approaches such as XGBoost instead of relying blindly on simple sampling. In practice, none is automatically best: compare alternatives using a suitable validation strategy. 6. SMOTE — the lecture's preview
The instructor explicitly says that SMOTE will be discussed in the next class. The following is an additional technical explanation, not a claim that the full SMOTE lesson was covered in this recording.
6.1 What does SMOTE do?
SMOTE stands for Synthetic Minority Over-sampling Technique.
Unlike random oversampling, which repeats existing rows, SMOTE generates synthetic minority-class examples by interpolating between minority-class points.
6.2 How it works
1. Select a minority-class sample \(x_i\).
2. Find its \(k\) nearest neighbours among minority-class samples.
3. Select one neighbour \(x_{zi}\).
4. Generate a new point between the two samples.
$$
x_{\text{new}}=x_i+\lambda(x_{zi}-x_i)
$$

where \(0\leq\lambda\leq1\) is randomly selected.
6.3 Simple numerical example
Suppose two minority-class samples have these two features:
- Sample A: \((2,4)\)
- Sample B: \((6,8)\)
If \(\lambda=0.5\), then:
$$
x_{\text{new}}=(2,4)+0.5((6,8)-(2,4))
$$

$$
=(2,4)+(2,2)=\boxed{(4,6)}
$$

The generated point lies halfway between A and B.
Illustration: SMOTE creates a point between minority examples rather than simply copying one of them.

6.4 Important limitations
- Synthetic points are not guaranteed to represent real-world cases.
- SMOTE can be problematic when minority and majority classes overlap or minority data contain noise.
- Ordinary SMOTE assumes numeric feature geometry; categorical features may need a suitable variant such as SMOTENC.
- Apply resampling only to the training portion of each split or cross-validation fold. Resampling the whole dataset before splitting can leak information into evaluation data and produce misleading scores.

7. Cost-sensitive learning
7.1 The core idea
In ordinary classification, a model's objective may treat different types of errors similarly, depending on the loss function and training setup.
But in the real world, different mistakes can have very different consequences.
Cost-sensitive learning makes the learning process account for these differences by assigning different penalties or weights to errors or examples.
The lecture's central message is:
A model should pay more attention to the mistakes that are more costly for the business.

7.2 The Class VIII pocket-money analogy
The instructor describes a student whose parents want him to become an engineer.
The parents set two different penalties:
- Low marks in Social Science: deduct ₹100.
- Low marks in Science and Mathematics (PCM): deduct ₹1,000.
Why is the penalty different? Because the parents consider Science and Mathematics more directly related to their goal.
Let's map the analogy carefully:
Analogy    Machine learning interpretation
Student    Learning algorithm
Subjects    Different types of prediction outcomes or errors
Parents' engineering goal    Business objective
Pocket-money deduction    Error penalty or cost
₹100 deduction    Lower-cost error
₹1,000 deduction    Higher-cost error
The student's objective, within this simplified analogy, is to avoid deductions and retain pocket money. The parents use different penalties to encourage performance in the subjects they consider most important.
Similarly, a learning algorithm minimising a weighted loss receives a stronger penalty for outcomes assigned greater cost.
Where the analogy has limits: Human students can react emotionally, become stressed or change their behaviour in ways that a mathematical loss function does not represent. The analogy illustrates unequal penalties; it is not a literal description of how a machine learning algorithm learns.
7.3 Mapping the analogy to fraud detection
The lecture uses the following example:
- 950 genuine transactions
- 50 fraudulent transactions
It assigns different costs to two kinds of errors.
Actual transaction    Model prediction    Error type    Illustrative cost
Genuine    Fraud    False Positive (FP)    ₹100
Fraud    Genuine    False Negative (FN)    ₹10,000
False Positive (FP): A genuine transaction is incorrectly flagged as fraud. The customer may face inconvenience, such as a temporarily blocked card.
False Negative (FN): A fraudulent transaction is incorrectly classified as genuine. The fraud may go undetected, resulting in financial loss.
The ratio in this example is:
$$
\frac{\text{FN cost}}{\text{FP cost}}
=\frac{10{,}000}{100}=100
$$

Thus, the illustrative false-negative cost is 100 times the false-positive cost.
7.4 Why the cost ratio matters
Consider two hypothetical models:
Model    False Positives    False Negatives    Total illustrative error cost
A    20    2    \(20(100)+2(10{,}000)=₹22{,}000\)
B    80    0    \(80(100)+0(10{,}000)=₹8{,}000\)
Model B produces more false alarms but has a lower total cost under the lecture's assumed penalties.
This is why the model with the highest accuracy—or even the fewest total errors—is not necessarily the best business choice.
The numbers here are illustrative. A real deployment would need to estimate costs carefully and account for operational constraints, such as how many fraud alerts a team can investigate.
7.5 How can we implement cost-sensitive learning?
The lecture specifically mentions weighted loss in Logistic Regression.
A practical implementation can assign different class weights or sample weights so that errors involving the important class influence training more strongly. Scikit-learn's LogisticRegression supports class_weight and sample_weight; its "balanced" option automatically weights classes inversely according to their observed frequencies.

7.6 Cost-sensitive learning versus sampling
Sampling-based methods    Cost-sensitive methods
Change the composition of the training data    Change how errors or examples are weighted
Examples: undersampling, random oversampling, SMOTE    Examples: class weights, sample weights, cost-aware decisions
May remove information or create repeated/synthetic samples    Can retain the original training records
Does not directly express every business cost    Can represent unequal error importance more directly
Neither approach is universally superior. They can also be combined, provided the resulting training and evaluation process is designed carefully.

10. Recommended practical workflow
When facing an imbalanced classification dataset with missing values, a disciplined workflow is:
1. Understand the data: inspect missingness, class counts and the business meaning of the target.
2. Create a train/test split: use stratification where appropriate so both sets contain representative class proportions.
3. Build a baseline: start with simple imputation and a reasonable classifier.
4. Choose evaluation metrics: inspect the confusion matrix, precision, recall, F1 and suitable imbalance-aware metrics rather than relying only on accuracy.
5. Compare missing-value strategies: evaluate mean/median imputation against KNN Imputation where suitable.
6. Compare imbalance strategies: try class weights, sampling methods and other appropriate alternatives.
7. Prevent data leakage: fit preprocessing and sampling only on training data; during cross-validation, fit them separately within each training fold.
8. Tune and evaluate: choose hyperparameters and decision thresholds using validation data.
9. Evaluate once on held-out test data: keep that test set representative of the real-world distribution rather than artificially balancing it.
10. Review business impact: confirm that the chosen model's false alarms, missed positives and operating costs are acceptable.
The imbalanced-learn documentation includes guidance on sampling, metrics, cross-validation and data-leakage pitfalls.

11. Quick revision sheet
- Imputation: filling missing feature values with estimates.
- KNN Imputation: estimate a missing value from similar rows.
- \(k\): number of neighbours considered, subject to having usable values for the feature.
- Uniform imputation: all selected neighbours contribute equally.
- Distance-weighted imputation: closer neighbours contribute more.
- Multiclass KNN: select the class with the strongest neighbourhood vote.
- Curse of dimensionality: in high-dimensional spaces, distance-based similarity can become less useful.
- Imbalanced data: one class is much more frequent than another.
- Undersampling: remove majority-class examples.
- Random oversampling: duplicate minority-class examples.
- SMOTE: create synthetic minority examples through interpolation.
- Cost-sensitive learning: make costly errors matter more to the learning or decision process.
- False Positive: genuine case predicted as positive.
- False Negative: positive case predicted as negative.
- Most important principle: select a model using appropriate validation metrics and real-world costs, not accuracy alone.
Final takeaway
This lecture connects three practical decisions in machine learning: how to handle missing data, how to classify multiple classes, and how to train/evaluate a classifier when errors do not occur equally or cost equally.
The main lesson is not that one technique always wins. It is to understand what each technique changes, what risks it introduces, and how to test whether it improves the model for the actual problem.
