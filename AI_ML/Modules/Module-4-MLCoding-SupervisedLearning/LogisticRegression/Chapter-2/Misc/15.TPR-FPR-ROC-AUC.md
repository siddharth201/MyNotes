# TPR, FPR, ROC & AUC — Simple Tutorial

## 1. First, where are we coming from?

You already know the Confusion Matrix:

```text
Actual → Predicted

11 → TP
01 → FP
10 → FN
00 → TN
```

And:

**Precision** = TP / (TP + FP)

**Recall** = TP / (TP + FN)

Now we introduce two new terms:

- **TPR**
- **FPR**

The first one is actually something you already know.

---

# 2. TPR — True Positive Rate

TPR asks:

> **"Out of all the actual Positive cases, how many did my model identify?"**

Formula:

**TPR = TP / (TP + FN)**

But wait...

That's exactly your **Recall** formula!

Therefore:

> **TPR = Recall**

So whenever you see:

**TPR**

just think:

> **"How many actual Positives did I catch?"**

---

### Example

Suppose:

```text
TP = 80
FN = 20
```

There were:

80 + 20 = 100 actual Positives.

The model found 80.

Therefore:

**TPR = 80 / 100 = 80%**

So:

**TPR = Recall = 80%**

---

# 3. FPR — False Positive Rate

This is the new one.

FPR asks:

> **"Out of all the actual Negative cases, how many did my model incorrectly classify as Positive?"**

Formula:

**FPR = FP / (FP + TN)**

Notice the denominator:

**FP + TN**

Why?

Because both are **actual Negative cases**:

```text
Actual 0 → Predicted 1 = FP
Actual 0 → Predicted 0 = TN
```

So:

**FP + TN = All Actual Negatives**

---

# 4. Think of FPR as "False Alarm Rate"

This is the easiest way to remember FPR.

Suppose:

```text
Actual = No Disease
Model = Disease
```

That's:

**0 → 1 = FP**

It's a **false alarm**.

So FPR asks:

> **"Among all people who were actually negative, how many did I falsely flag as positive?"**

---

# 5. TPR vs FPR

This is the most important distinction.

### TPR

> **How many actual Positives did I correctly catch?**

### FPR

> **How many actual Negatives did I incorrectly flag as Positive?**

So:

```text
TPR → Catching Positives
FPR → Creating False Alarms
```

---

# 6. Your Confusion Matrix makes it easy

```text
                 Predicted
              0           1

Actual  0     TN          FP
        1     FN          TP
```

### TPR

Look at the **Actual Positive row**:

```text
FN + TP

TPR = TP / (TP + FN)
```

### FPR

Look at the **Actual Negative row**:

```text
TN + FP

FPR = FP / (FP + TN)
```

This is a very useful visual memory.

---

# 7. Now comes the difficult part: Threshold

This is where the three videos connect.

Logistic Regression doesn't initially say:

> "Yes" or "No"

It gives a **probability**.

For example:

```text
Person A → 0.90
Person B → 0.80
Person C → 0.70
Person D → 0.40
Person E → 0.30
```

Then we choose a **threshold**.

For example:

**Threshold = 0.5**

Rule:

```text
Probability >= 0.5 → Positive
Probability < 0.5  → Negative
```

But we could choose:

```text
0.3
0.4
0.5
0.6
0.7
...
```

And every threshold produces a **different confusion matrix**.

Therefore:

> **Every threshold gives us a different TPR and FPR.**

And THAT is the foundation of the ROC curve.

---

# 8. Let's use the lecture's example

The lecturer creates a small dataset something like this:

| Sample | Actual | Probability |
|---|---:|---:|
| X1 | 1 | 0.6 |
| X2 | 1 | 0.7 |
| X3 | 1 | 0.5 |
| X4 | 0 | 0.4 |
| X5 | 0 | 0.1 |
| X6 | 0 | 0.2 |

We have:

```text
Actual Positive = 3
Actual Negative = 3
```

And the model gives probabilities.

Now let's sort by probability:

| Sample | Actual | Probability |
|---|---:|---:|
| X2 | 1 | 0.7 |
| X1 | 1 | 0.6 |
| X3 | 1 | 0.5 |
| X4 | 0 | 0.4 |
| X6 | 0 | 0.2 |
| X5 | 0 | 0.1 |

Now the ROC idea becomes much easier.

---

# 9. Threshold = 0.7

Only:

```text
0.7 → Positive
```

Others → Negative.

So:

```text
TP = 1
FN = 2
FP = 0
TN = 3
```

### TPR

TPR = 1 / (1 + 2)

= **1/3 ≈ 0.33**

### FPR

FPR = 0 / (0 + 3)

= **0**

So our ROC point is:

```text
(FPR, TPR) = (0, 0.33)
```

---

# 10. Lower threshold to 0.6

Now:

```text
0.7 → Positive
0.6 → Positive
```

Therefore:

```text
TP = 2
FN = 1
FP = 0
TN = 3
```

TPR:

**2/3 ≈ 0.67**

FPR:

**0**

ROC point:

```text
(0, 0.67)
```

---

# 11. Lower threshold to 0.5

Now:

```text
0.7 → Positive
0.6 → Positive
0.5 → Positive
```

All actual positives are detected.

```text
TP = 3
FN = 0
FP = 0
TN = 3
```

Therefore:

**TPR = 3/3 = 1**

**FPR = 0/3 = 0**

ROC point:

```text
(0, 1)
```

🎯 That's a perfect situation.

We found all positives without generating any false positives.

---

# 12. Now lower the threshold further

Suppose threshold becomes:

**0.4**

Now X4 also becomes Positive.

But X4 is actually Negative.

So:

```text
TP = 3
FN = 0
FP = 1
TN = 2
```

TPR:

**3/3 = 1**

FPR:

**1/3 ≈ 0.33**

ROC point:

```text
(0.33, 1)
```

Notice what happened.

We didn't gain any more TPR because we already caught all positives.

But:

**FPR increased.**

That's the trade-off.

---

# 13. Keep lowering the threshold

At threshold 0.2:

```text
TP = 3
FN = 0
FP = 2
TN = 1
```

TPR:

**1**

FPR:

**2/3**

At threshold 0.1:

Everything becomes Positive.

```text
TP = 3
FN = 0
FP = 3
TN = 0
```

TPR:

**1**

FPR:

**1**

---

# 14. Now plot these points

Our points are approximately:

```text
Threshold   FPR     TPR

>0.7        0       0
0.7         0       0.33
0.6         0       0.67
0.5         0       1
0.4         0.33    1
0.2         0.67    1
0.1         1       1
```

Put:

**FPR on X-axis**

and:

**TPR on Y-axis**

You get the **ROC curve**.

---

# 15. What is ROC?

ROC stands for:

> **Receiver Operating Characteristic**

Don't worry about the strange name.

For ML, remember:

> **ROC curve shows the relationship between TPR and FPR at different classification thresholds.**

So:

```text
Y-axis → TPR
          ↑
          |
          |
          |
          +--------------→ FPR
```

This is exactly what the lecturer draws in the second video.

---

# 16. Why do we need ROC?

Because we learned earlier:

### Lower threshold

Usually:

**Recall/TPR ↑**

but:

**FPR ↑**

### Higher threshold

Usually:

**Recall/TPR ↓**

but:

**FPR ↓**

So there is a trade-off.

ROC allows us to visualize this trade-off **across many thresholds**.

---

# 17. The ROC curve is basically telling us:

> "If I change my threshold, how much True Positive Rate can I get, and how many False Positives do I have to accept?"

That's it.

---

# 18. What does a good ROC curve look like?

We want:

**High TPR**

and

**Low FPR**

Ideally:

```text
TPR = 1
FPR = 0
```

That means:

> We caught all actual positives and produced zero false alarms.

That's perfect.

Graphically, we want the curve to go toward the **top-left corner**.

```text
TPR
1 |        ●────────
  |       /
  |      /
  |     /
  |    /
0 |___/____________ FPR
  0              1
```

---

# 19. What is the diagonal line?

You'll notice in the lecture a diagonal line:

```text
(0,0)
   \
    \
     \
      \
       (1,1)
```

This represents a **random classifier**.

Its AUC is:

**0.5**

So roughly:

```text
AUC = 1.0 → Excellent / perfect
AUC = 0.9 → Very good
AUC = 0.7 → Reasonable
AUC = 0.5 → Random
AUC < 0.5 → Worse than random
```

For now, don't obsess over exact "good" cutoffs; the important conceptual point is **1 is best, 0.5 is random**.

---

# 20. Now: What is AUC?

AUC means:

> **Area Under the ROC Curve**

That's literally what it means.

If the ROC curve is:

```text
TPR
1 |       ______
  |      /
  |    /
  |  /
0 |_/____________ FPR
  0              1
```

The area underneath that curve is the:

**AUC**

---

# 21. Why do we care about the area?

Because instead of looking at hundreds of thresholds individually, AUC gives us **one number to summarize the model's ability to separate Positive and Negative classes across thresholds**.

So:

```text
Many thresholds
      ↓
Many TPR/FPR points
      ↓
ROC curve
      ↓
Area under curve
      ↓
AUC
```

  |     /────────

  |   /     Model A
  |  /     /

# 23. A very useful intuition for AUC

There's another interpretation that is worth knowing:

> **AUC roughly represents the probability that the model will give a randomly chosen Positive a higher score than a randomly chosen Negative.**

For example:

**AUC = 0.90**

roughly means:

> If I randomly pick one Positive and one Negative, the model will rank the Positive higher about **90% of the time**.

This is a very nice way to understand AUC.

## Important

## What does a model with a High ROC-AUC mean?

**ROC-AUC** measures how well a classification model can **distinguish between the positive and negative classes across different classification thresholds**.

### Simple meaning

A model with a **high ROC-AUC** is generally good at **ranking positive examples above negative examples**.

For example, suppose we're predicting whether a patient has a disease.

The model gives:

| Patient | Actual | Model Score |
|---|---|---:|
| A | Positive | 0.95 |
| B | Positive | 0.82 |
| C | Negative | 0.30 |
| D | Negative | 0.10 |

The model has given **higher scores to positives and lower scores to negatives**.

That's what a high ROC-AUC represents.

### The important interpretation

Think of ROC-AUC as:

> **"If I randomly pick one positive and one negative example, how likely is my model to give the positive example a higher score than the negative example?"**

Approximately:

- **AUC = 1.0** → almost/perfectly separates the classes
- **AUC = 0.9** → excellent discrimination
- **AUC = 0.7** → reasonably good discrimination
- **AUC = 0.5** → no better than random ranking
- **AUC < 0.5** → systematically ranking in the wrong direction

### ⚠️ One important distinction

High ROC-AUC **does NOT necessarily mean**:

> "The model has high accuracy."

And it does **not** mean that the model's predicted probabilities are well calibrated.

It primarily means:

> **The model is good at distinguishing/ranking positive examples higher than negative examples.**

### 🎯 Interview-friendly definition

> **ROC-AUC measures a classifier's ability to distinguish between positive and negative classes across different classification thresholds. A high ROC-AUC indicates strong discriminative ability.**

For your assignment, if an option says:

> **"A model with a high ROC-AUC score can effectively distinguish between positive and negative classes."**

That is **True**.
